# en/ —— 英文站的全部文案

英文页 `/en/**` 上的每一个字都在这个文件夹里。模板只有中文一份，构建时按「原文 → 译文」把中文串换成英文，所以结构、图表、分数数据永远只有一处来源，不会中英漂移。

```
en/
  shell.json                        导航、页脚、首页、素材页，以及各期共用的按钮与栏目名
  reports/<slug>.json               这一期的正文、图表标签，以及它 meta.json 里的标题/标签/摘要
```

文件名里的 `<slug>` 必须和 `reports/` 下的目录名一致，构建才找得到。

## 怎么改英文

改文案就改这里的值，不要动中文模板。

```jsonc
{
  "看总榜": "Leaderboard",          // 键 = 模板里的中文原文，值 = 英文
  "第 %n 期": "Issue %n",           // %n 这类占位符要原样保留，构建时填数字
  "流萤King": ""                    // 值留空 = 有意保持中文
}
```

四条规矩：

1. **键要和模板里的中文逐字一致**。键里的空白按「一处或多处空白」匹配，所以模板里折行的长句，抄成一行就行。
2. **值留空表示有意保持中文**。评审昵称、AI 感检测器的句式清单和示例文本都属于这一类——它们是被检测的对象，翻译了就失真。以 `_` 开头的键是给人看的注释，不参与替换。
3. **键里带引号的是代码片段**（例如 `"（第`、`return "极差 " + m.range;`），它的值必须用直引号，保持 JS 语法完整；**纯文案里的引号一律用弯引号 `“ ”`**，直引号会把 JS 字符串撑破。
4. 长句先替换、短词后替换，所以整句能进词典就别拆成词。拆了容易在别处误伤。

## 加一期报告时

新建 `en/reports/<新 slug>.json`，把这期模板和 `meta.json` 里的中文翻一遍。跑 `node scripts/build.mjs`，末尾会列出英文页里还没进词典的中文字数，为 0 就是翻完了。

## 不需要翻的东西

参评作品原文、评审简评、`reports/<slug>/materials/` 里的素材，都保持中文——它们是被评的对象。构建时先翻模板，再把这些内容注入进去，词典碰不到它们。
